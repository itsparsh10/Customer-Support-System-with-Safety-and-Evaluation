Slide 1: Problem Statement, Objectives & Proposed Solution

⚠️ The Problem Statement

  • E-commerce platforms receive high volumes of customer inquiries on orders, returns, and refunds.
  • LLMs automate responses but risk generating hallucinated policies or leaking internal data.
  • Unprotected chatbots are prone to adversarial prompt injections and fraudulent concession bypasses.

🎯 Key Objectives

  • Integrate modern REST API LLM inference calls using Google Gemini API.
  • Develop a clean frontend-backend architecture with conversational memory.
  • Implement strict system prompt templates for role grounding.
  • Detect and halt prompt injections and jailbreak attempts.
  • Evaluate accuracy, latency, and API costs quantitatively.

💡 Proposed Solution: ApexMart AI Support Bot

A dual-layer security architecture combining pre-inference heuristic guardrails with Google Gemini 1.5 Flash. Malicious inputs are halted in sub-milliseconds without incurring API costs, while legitimate queries receive empathetic, policy-grounded support backed by a human supervisor escalation loop.

Slide 2: Tools, Technologies, Architecture & Workflow

🛠️ Technology Stack

  • Language: Python 3.12 within an isolated venv.
  • LLM API: Google Gemini 1.5 Flash via google-generativeai SDK.
  • Frontend: Streamlit interactive web application.
  • Configuration: python-dotenv for secure .env key storage.
  • Benchmarking: Pandas and Tabulate evaluation pipeline.

📐 Architectural Highlights

  • Zero-Leak System Prompts: Enforces return window (30 days) and refund timeline (5-7 days).
  • Heuristic Guardrail Layer: Fast regex filters catching DAN, system overrides, and PII leaks.
  • Live Telemetry: Sub-second latency tracking and micro-cent cost calculation.

🔄 End-to-End Workflow Pipeline

[Customer Query] ──► [Guardrail Engine] ──(Adversarial?)──► [Blocked Refusal + Escalation Queue] │ (Safe) ▼ [Gemini API + System Prompt Grounding] ──► [Post-Check] ──► [Streamlit UI + Telemetry]
